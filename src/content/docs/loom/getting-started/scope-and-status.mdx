Loom is a development tool. It renders your UI tree in a browser so you can iterate without a Studio
round-trip. Nothing it produces ships to Roblox, and its fidelity is deliberately partial.

<Callout title="Studio is still the source of truth">
A preview is a high-fidelity approximation of Roblox layout and painting, not a reimplementation of
the engine. Use it to iterate on structure, sizing, state and interaction. Verify final visuals in
Studio before shipping.
</Callout>

## Implemented

| Area | Status |
| --- | --- |
| Scene IR + WASM layout + DOM renderer | Complete — the vertical slice all frontends share. |
| Roblox datatypes, `Instance` model, signals, services, scheduler, Luau globals | Complete enough to run real component libraries. |
| `@rbxts/react` adapter | Complete: a custom `react-reconciler` host config driving live loom instances. |
| Layout: list, grid, padding, constraints, `AutomaticSize`, text measurement | Complete. |
| Visuals: text, `UICorner`, `UIStroke`, `UIShadow`, gradients, clipping, transparency, rotation, scrolling frames | Complete. |
| Images: `ImageLabel` / `ImageButton`, `ScaleType`, `ImageColor3`, `rbxassetid://` | Painted. See the gaps below. |
| Text: `FontFace`, `RichText` markup, wrapping, `LineHeight` and measurement | Complete. |
| Fonts: `registerFont`, `@loom-dev/renderer/fonts` | Shipped in `0.6.4`. The host installs the engine's typefaces; unbacked families warn. |
| Flex: `UIListLayout` flex and `Wraps`, `UIFlexItem` | Complete. |
| `TweenService`, bindings, `@rbxts/ripple` | Complete. |
| Pointer and keyboard input, focus, `UserInputService` | Complete, with Roblox input-sinking semantics. |
| Dev loop: Vite plugin, HMR, `loom preview`, `loom build` | Complete. |
| `vide` adapter | Shipped, on the same Scene IR. |

Those rows are area-level. For the per-property answer — is `AutomaticCanvasSize` honored, does
`UIGradient.Rotation` work, what happens to `ScrollBarThickness` — see [Supported instances and
properties](/loom/reference/supported-properties/).

The practical proof point: a full headless component library — dialogs, popovers, comboboxes,
selects, tabs, sliders, focus scopes, portals and layers — renders and behaves correctly under `loom
preview`, across more than fifty scenes, without a single source change on the library's side.

## Not implemented

**Sprite sheets and 9-slice.** Images paint as of `0.6.0`, but `ScaleType.Slice` and `ScaleType.Tile`
fall back to `Stretch`, and the `ImageRectOffset` / `ImageRectSize` sprite window is ignored — each
needs more than one `<img>` layer. An icon cut out of a sheet renders as the whole sheet.

**`UIPageLayout` and `UITableLayout`.** Both are recognized by the layout engine — they will not
crash — but neither does anything. Children of a `UIPageLayout` will not page.

**`UIScale`.** A valid JSX intrinsic with typed props, and a no-op: nothing reads `UIScale.Scale`, so
a scaled subtree renders at 1×. (`UIFlexItem`, which used to sit in this row, is implemented as of
`0.5.0`.)

**`TextScaled`.** Accepted on every text class and never applied — text renders at `TextSize`
whether or not it fits.

**`Gotham`, out of the box.** Roblox's default family is proprietary and cannot be redistributed, so
`@loom-dev/renderer/fonts` covers only the openly licensed families. A project that has the files
registers them itself — see [Fonts and text metrics](/loom/guides/fonts/).

**A roblox-ts compiler transform.** The preview path deliberately skips `rbxtsc` and lets esbuild
transpile. A standalone transform, which would let loom consume compiled output rather than source,
is still open.

**A Luau adapter.** The IR was designed so a Luau frontend can be added. It has not been.

## Things that are true, not bugs

- **No typechecking.** esbuild strips types; a preview renders whether or not your project typechecks.
  See [TypeScript setup](/loom/guides/typescript-setup/).
- **`print` types oddly.** The globals declaration deliberately omits `print` because `lib.dom`
  already declares one and redeclaring is a compile error. The runtime still overwrites the value.
- **Unknown services are stubs.** `@rbxts/services` is aliased to a module exporting only the
  [services the runtime actually implements](/loom/reference/services/) — `CollectionService`,
  `ContextActionService`, `GuiService`, `HttpService`, `Players`, `RunService`, `TweenService`,
  `UserInputService`, `Workspace`. Importing anything else is a build error rather than a silent
  stub, which is the intended trade.
- **A Luau-only package needs a shim.** Most roblox-ts packages redirect to their own TypeScript
  source automatically; a declaration-only one has no source to redirect to and fails by name until
  you point [`shims`](/loom/guides/package-compatibility/#shims) at a browser module. `@rbxts/react`,
  `@rbxts/react-roblox`, `@rbxts/services`, `@rbxts/vide`, `@rbxts/ui-labs`, `@rbxts/ripple` and
  `@rbxts/react-ripple` are handled out of the box.
- **`rbxassetid://` needs a server.** Roblox's thumbnail API sends no CORS headers, so the id is
  resolved by a dev-server route the preview installs — under `loom preview`, the embedded server and
  Next dev. A [static gallery build](/loom/guides/static-builds-and-embedding/) has no server to ask:
  pass real URLs there, or install your own resolver with `setImageResolver`.
- **The React version is pinned in effect.** The adapter's reconciler targets React 18; the plugin
  aliases bare `react` to one absolute path to guarantee a single instance.
- **Text metrics are the browser's.** Loom measures with canvas `measureText()`, so shaping and
  rounding differ from the engine by a glyph here and there even with the right typeface installed.
  Installing it is the part that matters: without it the fallback is a *different* typeface per OS,
  and the layout moves with it.

## Versioning

All `@loom-dev/*` packages release in lockstep — the changesets configuration marks them `fixed`, so
a bump to one bumps them all. Mismatched versions across the scope are never a supported combination.
The project is pre-1.0: expect the plugin's config contributions and the gallery URL contract to be
the stable-ish parts, and internal package boundaries to move.
