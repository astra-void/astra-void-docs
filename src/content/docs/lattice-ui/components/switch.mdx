Switch is the primitive for an on/off toggle. The root is the toggleable track that owns checked
state, and the thumb slides between its two ends; everything visual is yours. Reach for it when a
control is **boolean**, should **toggle on activation**, and wants a **thumb that animates**. For a
third `"indeterminate"` state or a reveal-style indicator,
[Checkbox](/lattice-ui/components/checkbox/) fits better.

## Import

```ts

```

## Anatomy

`Root` is the toggleable track and is the only required part. `Thumb` is the sliding handle; include it whenever you want the moving indicator.

<PrimitiveAnatomy title="Switch anatomy">

```tsx title="Switch anatomy"
<Switch.Root>
  <Switch.Thumb />
</Switch.Root>
```

| Part | Required | Responsibility |
| --- | --- | --- |
| `Switch.Root` | yes | The track button: owns checked state and toggles on activation. |
| `Switch.Thumb` | no | The handle that animates between the off and on ends of the track. |

</PrimitiveAnatomy>

## Examples

### Basic usage

Uncontrolled state seeded with `defaultChecked`, plus just enough styling to see it. The root
renders a `textbutton` and the thumb a `frame`, both unstyled, so without a size and colours the
switch works but draws nothing.

```tsx title="BasicSwitch.tsx"
import { Switch } from "@lattice-ui/react-switch";

export function BasicSwitch() {
  return (
    <Switch.Root
      BackgroundColor3={Color3.fromRGB(66, 73, 91)}
      defaultChecked={true}
      onCheckedChange={(checked) => print(`switch is now: ${checked}`)}
      Size={UDim2.fromOffset(48, 24)}
    >
      <uicorner CornerRadius={new UDim(1, 0)} />
      <Switch.Thumb
        BackgroundColor3={Color3.fromRGB(240, 244, 252)}
        Size={UDim2.fromOffset(20, 20)}
      >
        <uicorner CornerRadius={new UDim(1, 0)} />
      </Switch.Thumb>
    </Switch.Root>
  );
}
```

### Controlled settings toggle

Pass `checked` and `onCheckedChange` when something outside needs to read or set the value. Here a
music toggle keeps local state for instant feedback and forwards every change to a save callback.

```tsx title="MusicToggle.tsx"
import { useState } from "@rbxts/react";
import { Switch } from "@lattice-ui/react-switch";

export function MusicToggle(props: { onSave: (enabled: boolean) => void }) {
  const [enabled, setEnabled] = useState(true);

  return (
    <frame BackgroundTransparency={1} Size={UDim2.fromOffset(280, 36)}>
      <uilistlayout
        FillDirection={Enum.FillDirection.Horizontal}
        Padding={new UDim(0, 12)}
        VerticalAlignment={Enum.VerticalAlignment.Center}
      />

      <textlabel
        BackgroundTransparency={1}
        Size={UDim2.fromOffset(100, 20)}
        Text="Music"
        TextColor3={Color3.fromRGB(236, 241, 249)}
        TextXAlignment={Enum.TextXAlignment.Left}
      />

      <Switch.Root
        BackgroundColor3={enabled ? Color3.fromRGB(86, 141, 255) : Color3.fromRGB(66, 73, 91)}
        checked={enabled}
        onCheckedChange={(checked) => {
          setEnabled(checked);
          props.onSave(checked);
        }}
        Size={UDim2.fromOffset(48, 24)}
      >
        <uicorner CornerRadius={new UDim(1, 0)} />
        <Switch.Thumb
          BackgroundColor3={Color3.fromRGB(240, 244, 252)}
          Size={UDim2.fromOffset(20, 20)}
        >
          <uicorner CornerRadius={new UDim(1, 0)} />
        </Switch.Thumb>
      </Switch.Root>
    </frame>
  );
}
```

### Custom track and thumb with asChild

Use `asChild` on the root for a `frame` track rather than a `textbutton`, and on the thumb to slide
your own handle. Track colour is always yours, so branch on the controlled state directly. The thumb
still animates — its travel resolves to the track width minus the thumb width, whatever size you
make either.

```tsx title="StyledSwitch.tsx"
import { useState } from "@rbxts/react";
import { Switch } from "@lattice-ui/react-switch";

export function StyledSwitch() {
  const [enabled, setEnabled] = useState(false);

  return (
    <Switch.Root checked={enabled} onCheckedChange={setEnabled} asChild>
      <frame
        BackgroundColor3={enabled ? Color3.fromRGB(52, 168, 108) : Color3.fromRGB(44, 48, 60)}
        BorderSizePixel={0}
        Size={UDim2.fromOffset(48, 24)}
      >
        <uicorner CornerRadius={new UDim(1, 0)} />
        <uistroke Color={Color3.fromRGB(88, 142, 255)} Thickness={1} />

        <Switch.Thumb asChild>
          <frame
            BackgroundColor3={Color3.fromRGB(240, 244, 252)}
            BorderSizePixel={0}
            Size={UDim2.fromOffset(20, 20)}
          >
            <uicorner CornerRadius={new UDim(1, 0)} />
          </frame>
        </Switch.Thumb>
      </frame>
    </Switch.Root>
  );
}
```

<Callout title="Track color is yours">
The root never animates its own `BackgroundColor3` — there are no track-colour props. Derive the colour from the checked state you already control, and animate it yourself if you want it to ease rather than snap.
</Callout>

### Disabled state

`disabled` blocks toggling entirely — activation is ignored, `setChecked` calls from context are
dropped — and removes the switch from gamepad selection. Nothing about the appearance changes on its
own, so render the inert look yourself.

```tsx title="PremiumToggle.tsx"
import { Switch } from "@lattice-ui/react-switch";

export function PremiumToggle(props: { hasPremium: boolean }) {
  const disabled = !props.hasPremium;

  return (
    <Switch.Root
      BackgroundColor3={disabled ? Color3.fromRGB(84, 90, 106) : Color3.fromRGB(66, 73, 91)}
      defaultChecked={false}
      disabled={disabled}
      Size={UDim2.fromOffset(48, 24)}
    >
      <uicorner CornerRadius={new UDim(1, 0)} />
      <Switch.Thumb
        BackgroundColor3={Color3.fromRGB(240, 244, 252)}
        Size={UDim2.fromOffset(20, 20)}
      >
        <uicorner CornerRadius={new UDim(1, 0)} />
      </Switch.Thumb>
    </Switch.Root>
  );
}
```

### Custom thumb size

The thumb's slide is a fixed short settle with no transition prop, but the geometry adapts to your
handle: travel resolves to the track width minus the thumb width, and the thumb stays vertically
centred at any height.

```tsx title="LargeThumbSwitch.tsx"
import { useState } from "@rbxts/react";
import { Switch } from "@lattice-ui/react-switch";

export function LargeThumbSwitch() {
  const [enabled, setEnabled] = useState(false);

  return (
    <Switch.Root checked={enabled} onCheckedChange={setEnabled} asChild>
      <frame BackgroundColor3={Color3.fromRGB(66, 73, 91)} BorderSizePixel={0} Size={UDim2.fromOffset(64, 32)}>
        <uicorner CornerRadius={new UDim(1, 0)} />

        <Switch.Thumb asChild>
          <frame
            BackgroundColor3={Color3.fromRGB(240, 244, 252)}
            BorderSizePixel={0}
            Size={UDim2.fromOffset(28, 28)}
          >
            <uicorner CornerRadius={new UDim(1, 0)} />
          </frame>
        </Switch.Thumb>
      </frame>
    </Switch.Root>
  );
}
```

## How it behaves

### Checked state

Controllable on `checked`/`onCheckedChange`, with `defaultChecked` for uncontrolled usage. The state
is a plain boolean that activation flips. While `disabled`, both the toggle and direct `setChecked`
calls are ignored.

### Activation and selection

`Switch.Root` renders an activatable `textbutton` that toggles on `Activated`, so click, tap and
gamepad activation all work. It carries no size, colour or label of its own, and is `Active` and
`Selectable` only while enabled.

Under `asChild` the slot's `Active`, `Selectable` and ref win over the child's props, and event
handlers compose. Use an element that fires `Activated`.

### Track color

The track's `BackgroundColor3` is entirely yours. Derive it from the same `checked` state you pass in, and animate it yourself if you want it to ease rather than snap.

<Callout title="Removed in 0.7.0">
`trackColorMode`, `trackOnColor`, `trackOffColor` and `disabledTrackColor` no longer exist on `Switch.Root`, and neither does the `SwitchTrackColorMode` type. See [Migration](/lattice-ui/reference/migration/).
</Callout>

### The thumb

`Switch.Thumb` animates between the ends of the track as `checked` changes: checked parks its
trailing edge on the track's trailing edge, unchecked its leading edge on the leading edge. Because
`AnchorPoint` and `Position` interpolate together, travel resolves to the track width minus the
thumb width for **any** thumb width — so one sized through a child element, a constraint or a layout
works as well as one with a declared `Size`. The same pairing on Y keeps it centred at any height.

Motion owns `AnchorPoint` and `Position` under a `layout` target contract, so both are dropped from anything you pass rather than being written and clobbered on the next frame. Style the thumb with size, color, corners and children instead.

Under `asChild` the primitive wraps your element in a transparent frame it animates and pins your
element to `Position` (0, 0) inside it — style the child, but leave its `Position` alone. The thumb
is always mounted, so unlike `Checkbox.Indicator` there is no `forceMount`.

### Motion

The slide is a fixed 0.08s settle, so toggling feels immediate but smooth. Neither `Root` nor
`Thumb` exposes a `transition` — you shape the feel through geometry. Nothing else animates: the
track colour is yours, so any colour transition is yours to drive.

<Callout title="Roblox gotchas">
The root is a Roblox button, `Active` and `Selectable` only while enabled, so a disabled switch drops out of gamepad selection. Give the track a real size — the thumb's travel is measured against it.
</Callout>
