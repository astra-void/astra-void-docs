## `w-full h-fit`, all the way down

Every part carries it, and that is the layout strategy: **width from the parent, height from the
content**. Break the chain at any level and the card above it collapses.

A container hugging its content can only measure children that already know their own size, so it is
not enough for `Card` to say `h-fit` — every level under it has to answer too.

## Six parts, one recipe object

```tsx
export const cardVariants = {
  root: fv("flex-col w-full h-fit rounded-lg border border-border bg-card"),
  header: fv("flex-col w-full h-fit gap-1 p-6"),
  title: fv("w-full h-fit whitespace-normal text-left text-xl font-semibold text-card-foreground"),
  description: fv("w-full h-fit whitespace-normal leading-tight text-left text-xs font-normal text-muted-foreground"),
  content: fv("flex-col w-full h-fit gap-2 px-6 pb-6"),
  footer: fv("flex-row items-center w-full h-fit gap-2 px-6 pb-6"),
};
```

<Callout title="This is not a style choice">
Vela once inlined its whole runtime into every file with a computed `className`, leaving a component only a slice of Luau's 200-register limit. Six separate `export const`s put this file over it and the module stopped loading. Each exported name costs a register; one object costs one.

Emitted files now sit around 24 module-scope locals, which is why `^0.9.0` is the floor the CLI installs. The object shape stayed because it is cheap.
</Callout>

## Wrapping and alignment are classes

Roblox centres text and leaves it on one line, so `text-left` and `whitespace-normal` are on every
text part. Without them a description is one centred line running off the edge.

`leading-tight` on the description is the one place `card` leans on a Vela family that reached the
computed-`className` path in 0.8.0 — below that floor it compiles and silently does nothing.

`font-normal` on the description looks redundant beside `font-semibold` on the title, and is not:
Vela leaves `FontFace` alone when no `font-*` appears, and Roblox's default is LegacyArial — so the
description rendered in Arial beside a SourceSansPro title until someone opened it in Studio.

## One layout per instance

`flex-col`, `items-*`, `justify-*` and `gap-*` all lower onto a single `UIListLayout` child, and one
instance holds one layout. A part that sets any of them owns its children's arrangement, so a
consumer wanting a different one **replaces** those classes rather than adding to them.

Wanting a second layout inside `CardContent` is a sign to restructure the parts, which are yours to
restructure.
